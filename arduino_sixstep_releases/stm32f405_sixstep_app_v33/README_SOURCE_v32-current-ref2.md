# v32-current-ref2: tested v32 startup profile with signed-duty direction control and 10%/s duty ramp

This is a separate Arduino sketch copied from the tested v32 in `sixstepf405 80persen`. The original is not modified.

Open `sixstepf405_current.ino` in Arduino. Keep the original Generic STM32F405 board, USB CDC and ST-Link settings. PWM remains 20 kHz. The original PWM, BEMF detector and speed guard functions are retained.

## Startup profile

The motor startup/commutation profile in this sketch is restored to match the user-confirmed working `sixstepf405 80persen/sixstepf405.ino`: ALIGN 2% to 5% over 200 ms, startup average-duty cap 5%, duty slew 10 percentage points/s (0.1% every 10 ms), startup blanking period/8 limited to 150..1000 us, and the original forced-period ramp (up to 0.4% per eligible sector). The phase table, clamp, crossing qualification and six-consecutive-cross handover remain intact. Current-monitor and CTEST/CREF diagnostics are retained separately; no current trip is enabled. The known-good source file is not modified.

This is an experimental startup-profile change, not a guaranteed loaded-start controller. More duty can increase current; 10% is a duty cap, NOT a 10% or 5 A current limit. Current measurement remains diagnostic and unavailable during ALIGN/STARTUP. Keep the externally limited DC source <=5 A, start at DUTY 10 without load, verify repeated starts, then try a small secured mechanical load. If it vibrates or stalls, capture STATUS/DIAG before stopping/resetting and disconnect power if it heats. Do not increase DUTY to force a stalled start. No automatic retries are introduced. Actual acceleration and starting load capability require hardware verification.

## Scope and limitations

- User-reported power stage MOSFET: IRFS7530; intended load-current target 20 A. This is not a verified board continuous-current rating. Phase current versus battery current, PCB/shunt thermal capability, gate drive and actual load still need confirmation. No 20 A limit has been enabled while current acquisition remains unverified.
- PC0/PC1/PC2 are assumed to be current U/V/W; verify actual board routing.
- STOP: ADC1 regular scan uses channels 10/11/12, 56-cycle sample time, DMA2 Stream0 Channel0, about 100 scans/s for raw diagnostics and CZERO.
- CLOSED_LOOP: main loop requests up to about 1000 readings/s and arms ONE 15-cycle regular conversion for the NEXT PWM pulse, selecting PC0/1/2 from the current sector LOW phase. TIM1 TRGO update resets TIM3 via ITR0. TIM3 CH1 internal PWM2 OC1REF rises at 2 us; TRGO exports OC1REF and ADC1 uses TIM3_TRGO (EXTSEL 1000), rising edge. No GPIO is assigned to this internal PWM. RUN uses no SWSTART and does not wait for BEMF interrupt latency. Arming occurs after 8 us into this carrier and at least 8 us before rollover, with a sufficiently wide next ON pulse. ALIGN/STARTUP receive no new regular current conversions. Existing asynchronous scans are drained and discarded if motor operation starts.
- DMA completion interrupt (priority 3, below motor priority 2) disables regular EXTEN and validates completion within the EXPECTED next pulse and original sector, after the 2 us trigger, no later than 8 us into PWM and before PWM OFF. Late interrupts, invalid windows, rollover, commutation or DMA errors discard readings. Actual timer preload rollover, not prepared next width, tags the current pulse. Hardware trigger alignment, ADC latency, driver/amplifier switching settling at 2 us and the 15-cycle ADC source settling all require scope verification; no claimed overcurrent protection.
- TIM3 is reserved for this internal trigger (no GPIO or timer interrupt). Setup refuses to take a timer already running or with interrupt/DMA requests enabled. `CURRENT` shows timer_ready, ticks/us, arm/done/on_ticks to diagnose timing. If timer_ready=0, no PWM readings are taken; do not raise duty to bypass this.
- RUN CURRENT reports only the most recent valid selected channel with acquisition step, age, accepted/dropped/window_miss counters; data older than 100 ms is withheld. It is not a simultaneous U/V/W vector. Narrow pulses may yield no valid readings: do not raise duty just to force availability. STOP reports the original three-channel asynchronous data.
- DMA/zero calibration is nonblocking. A failed monitor disables itself and reports failures. If scanning is enabled and the motor is active, the main loop latches outputs OFF with CURRENT_MONITOR fault. This acquisition-failure interlock is NOT a current-limit or short-circuit protection system.
- `CURRENT` displays estimated signed amperes based on user-reported INA181A1 (gain 20) and 1 mOhm shunt, nominal VDDA 3300 mV and direct amplifier-to-ADC connection. Scale is about 0.0403 A/count. Verify VDDA, routing, attenuation and polarity; edit the named `CURRENT_*` scale constants if needed. Neither RUN nor STOP readings are RMS, supply DC current or guaranteed peak current. No current regulation or overcurrent trip is enabled. External current limiting is still required.
- Shared ADC regular activity still requires hardware timing/BEMF regression testing; compilation and emulation cannot prove it does not affect motor timing.

## Commands

- `-20`: select reverse and a 20% duty target. `+20` selects forward. The same forms with the keyword (`duty -20` / `duty +20`) are also accepted. Unsigned `20` or `duty 20` changes only the duty and preserves the selected direction. Direction changes are accepted only while stopped; a reversal request while the motor is active is rejected. Duty ramps at 10 percentage points/s.

### v10 DC calibration helpers

The user has observed increasing PWM-qualified readings under manual load, but this does not verify absolute current accuracy. v10 adds main-loop-only comparison tools; the working v9 PWM trigger/DMA path and BEMF timing are unchanged. No current trip or load/RPM controller is enabled.

- `CTEST`: requires stopped motor, CSCAN ON, successful CZERO, and no other collection. Captures 64 new STOP three-channel scans (~0.64 s), skipping any scan already in flight when requested. Reports each channel's raw min/max/spread, captured zero, signed delta sum and estimated arithmetic mean in mA. The mean uses the full sum with 64-bit arithmetic, not rounded individual ADC counts. No outliers are trimmed here: spread exposes instability, while zero calibration remains trimmed as before.
- `CRESULT`: prints the most recent completed CTEST again. All data is RAM-only. Partial/aborted tests are not usable; collections abort on monitor/scan/state change or after 2 s. RUN is rejected during collection. Starting CZERO invalidates the old CTEST result.
- `CREF U 1000` (or V/W, signed nonzero reference -5000..5000 mA): compares the last completed STOP test on that sensor channel with the measured current THROUGH THAT SHUNT. Prints estimated mean, signed error in mA, relative error in permille (10 permille = 1%), and polarity match. Near-rail data is rejected. This command does NOT set output current, change zero, gain or polarity, or save a calibration. The reference can be supplied after the collection has completed; do not reset/re-zero before comparing it.

Procedure: with no shunt current, STOP -> CSCAN ON -> CZERO; wait for ready. Once safe test routing through a selected shunt has been verified from the schematic, apply known stable DC current using an externally limited source and suitable series meter, then CTEST. After completion use CREF with the meter's signed reading in mA; repeat at several current levels and on U/V/W. CTEST at zero current checks residual offset, but CREF intentionally rejects a zero denominator. Never CZERO while nonzero test current is applied. Never inject current into the ADC or INA OUT pins. Do not energize inverter/motor gates for this DC test. Hardware routing must be established before making connections; software does not prove a safe current-injection path.

These are 56-cycle asynchronous STOP readings, NOT the 15-cycle PWM ON readings during RUN. Passing DC gain/offset comparison does not validate RUN settling, switching spikes, RMS, peak or DC-bus current. RUN requires separate oscilloscope/current-probe validation at the actual sample point. A supply's DC current indication during RUN is not a valid CREF reference. Retain external <=5 A bus limiting and do not use hands to load a rotating shaft.

v9 changes the trigger route after the v8 hardware snapshot showed TIM3 compare/trigger events but DMA NDTR remained 1 and no DMA interrupt occurred. That evidence does not uniquely establish the cause. The new route deliberately produces an OC1REF rising edge instead of relying on the frozen CC1 event path. Before each new regular transaction, regular EXTEN/DMA/DDS are cleared, then DMA is re-enabled after the stream is prepared. RUN uses DDS=0 for one-shot DMA; STOP uses DDS=1 for the three-channel sequence. Regular OVR/EOC/STRT flags are cleared selectively with W0C, preserving injected JEOC/JSTRT. ADC1 is never power-cycled and BEMF configuration is retained.

RUN CURRENT includes monitor ready/busy/failures and DMA IRQ entries. The first genuine current timeout/DMA error is saved BEFORE cleanup clears ADC external trigger and DMA controls. `CDIAG` (no arguments) reports the saved snapshot and separately labeled live registers: TIM1/TIM3, ADC1 regular configuration/status, DMA CR/NDTR/LISR, NVIC enable/pending and pulse epochs. STOP does not erase the snapshot; reset does. No automatic retry or longer timeout is added. A monitor failure with scanning enabled now stops the motor; scanning OFF still allows the BEMF baseline test.

For the user's <=5 A bring-up test, use an externally current-limited source set no higher than 5 A on the DC bus, start unloaded at DUTY 20, and keep a physical disconnect available. This does not constrain instantaneous phase current to 5 A; battery tests without external limiting are not equivalent. Do not connect the intended 20 A load yet. After reset: STOP, CSCAN ON, CZERO, wait for CURRENT ZERO ready, DUTY 20, ARM, RUN. Check CURRENT and STATUS briefly: accepted and dma_irq must increase, failures must remain 0, and BEMF must remain locked. If acquisition fails, STOP then CDIAG before reset. Compare readings to known applied current and check PWM/INA settling before enabling any software current trip. Compilation/emulation do not establish successful acquisition on the real board.

At each PWM arm, TIM3 CC1IF/TIF flags are cleared so a saved flag reflects an event since that arm. ADC SR is still cleared by the existing BEMF interrupt, so missing EOC/STRT bits cannot prove no regular conversion occurred. Snapshot code never reads ADC DR or clears DMA status and prints only outside critical sections/interrupts. A one-time failure message asks for CDIAG. Saved timeout reason 1 excludes expected STOP/sector-change cancellation.

v5 fixes a register-sharing race introduced in v4: OFF no longer rewrites ADC1 CR1/CR2 on every loop. Regular controls are cleared only once after a completed scan, and both this cleanup and regular SWSTART register updates use a short critical section so BEMF interrupt trigger updates cannot be overwritten. No BEMF detector thresholds, ADC timeout or motor-drive timing settings are relaxed. Hardware regression testing remains required; this patch does not establish that the race was the only fault cause.

Current scanning defaults **OFF** after reset. `CSCAN ON` and `CSCAN OFF` are accepted only when motor outputs are inactive. OFF drains an already-started scan and discards its result, then clears regular SCAN/DMA controls; no ADC power cycle or injected-trigger changes are made. RAM zero is retained across toggles. Disabled or not-yet-fresh readings are withheld. This isolates regular-conversion activity, not every initialization difference from original v32. A monitor failure is not cleared by toggling.

1. Send `STOP` and wait for the motor and phase current to settle.
   Send `CSCAN ON` to enable diagnostics/calibration.
2. Send `CURRENT` to inspect raw ADC values. No zero is assumed automatically.
3. Send `CZERO` while stopped, with no phase current. Collects 64 new scans, about 0.64 seconds. For each channel, sorts and excludes the lowest 8 and highest 8, then averages the central 48. Rejects any raw sample below 64 or above 4031, or a central-48 span above 48 ADC counts. RUN is rejected during calibration.
4. Wait for `CURRENT ZERO ready`, then send `CURRENT` to see zero, signed deltas in ADC counts and estimated signed amperes. An ampere value is withheld until zero is ready. A noise spike also converts to an apparent current; conversion alone does not validate the measurement.
5. Use the original `ARM`, `RUN`, `DUTY`, `STATUS` and `DIAG` commands. Start at low duty and verify BEMF stability before repeating higher-duty tests. Use `CURRENT` as needed; no automatic serial stream is enabled.

Zero calibration is RAM-only and must be repeated after reset. With no applied current, signed deltas should be near zero; compare all three channels and their noise. Supply DC current is not the same quantity as instantaneous phase current.

For BEMF regression comparison, first run at duty 20 with `CSCAN OFF`, without current printing; collect STATUS/DIAG after the test or fault. STOP, enable CSCAN ON, calibrate if needed, then repeat the same load/duty and duration without current printing. Compare repeat runs. Only then separately test CURRENT printing to distinguish regular-ADC activity from serial reporting. BEMF thresholds/timeouts and motor control remain unchanged; this is a diagnostic change, not proof the reported fault is fixed.

Calibration prints per-channel raw min/max/spread and trimmed min/max/spread on completion, even if rejected; `CURRENT` repeats these statistics. The 48-count trimmed-span limit replaces the old 24-count full-span limit to tolerate moderate variation and isolated non-rail spikes. It is a diagnostic acceptance threshold, not a validated current-protection setting. Persistent noise, drift or near-rail readings still require sensor/wiring investigation; calibration does not repair those faults.

Trigger references: ST RM0090 (general-purpose timer internal trigger connections and ADC regular external trigger table), and the bundled ST STM32F4 HAL `ADC_EXTERNALTRIGCONV_T3_TRGO`, `TIM_TRGO_OC1REF` and `TIM_OCMODE_PWM2` definitions. [ST timer synchronization guide](https://wiki.st.com/stm32mcu/wiki/Getting_started_with_TIM). STOP uses 56-cycle sampling whereas RUN uses 15 cycles; verify source impedance/settling and resulting offset before treating the nominal amp conversion as calibrated current.
